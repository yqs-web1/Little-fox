### 第三步：找到并修掉真 bug —— "没有可读内容"被当成"合成失败"

`sanitize_for_tts()` 会把纯表情/符号净化成空串（实测 `😊`、`😊🎉`、`**`、纯空白 → `''`）。而语音模式下：

```
speak_and_send('')        -> tts_local 对空文本直接 False
兜底 reply_send('')       -> reply._segments() 丢弃空串，一条都不发
=> 用户既没声音、也没文字（彻底静默）；~语音 <纯表情> 还会回"语音合成失败：请确认本机已联网"
```

修复（本机为 `Tools/tts_local.py` + `main.py` 四处调用点）：

1. `Tools/tts_local.py` 新增 **`speakable_text()`**：统一净化并返回"真正可朗读的文本"，空串表示没有可读内容；
   `tts_local()` 遇到这种情况**快速返回 False**（不再空跑 edge + pyttsx3 两条必败链路，实测从数秒降到 0.00s）。
2. `main.py` 四处调用点（私聊/群聊 × 语音对话 / `~语音` 命令）改为**先净化再判断**：

### 顺手澄清一个看着吓人的现象

### 3.3 改人格 / 人设（最常用，也最容易改错）

- **主入口：`prerequisites/Normal.txt`**。这就是系统提示词（system prompt）。支持 4 个占位符，运行时替换：

| 占位符 | 含义 |
|---|---|
| `{self.bot_name}` | `config.json` 的 `bot_name` |
| `{self.bot_name_en}` | `bot_name_en` |
| `{self.event_user}` | 当前说话人的昵称 |
| `{self.event_user_id}` | 当前说话人的 QQ 号 |

- **改完不用重启**：`main.py:753/860` 对**每条消息**都重新调用 `gen_presets()` 读文件，所以保存 `Normal.txt` 后下一条消息就是新人设。
- **多角色扮演**：`prerequisites/current.json` 是索引（`name`/`info`/`path`/`uid`），每个 `p*.txt` 是一个角色；用户在群里发 `~角色扮演` 看列表，发角色名切换；管理员可用 `~添加预设 名字 简介 : 内容`、`~删除预设 名字`。
- 现有预设建议清理：`p9360874.txt`（春日野悠）含明确的 NSFW/乱伦要求，属于平台违规高风险内容。

### 3.4 AI 后端与模型

- **优先用 QQ 命令，不用改文件**：`~云端` ↔ `~本地` ↔ `~后端状态`。切换会**同时**写回 `config.json` 并更新内存（`main.py:138-162`），无需重启。
- 纯本地：确保 LM Studio 已 `lms load <local_model>` 并开着 `http://localhost:1234/v1`。
- 纯云端：把 `cloud_base_url` / `cloud_model` / `deepseek_key` 填对，`ai_backend` 设 `cloud`。

```python

async def on_message(event, actions, Manager, Segments, order, ...):
    # 需要哪些参数就写哪些，main.py 会按名字从上下文里注入；
    # 可用：order, time, datetime, traceback, cooldowns, cooldowns1,
    #       Super_User, Manage_User, ROOT_User, ADMINS, SUPERS, bot_name, bot_name_en,

    if "我的命令" not in order:
```

关键机制（`main.py:471-503`）：

- 关键词写 `"Any"` 的插件对**每条消息**都执行（`main.py:654`，`LikePlugin` 就是这么做的），记得在不匹配时 `return False`。

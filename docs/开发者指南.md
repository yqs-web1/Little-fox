## 一、先读这一节：三个决定一切的架构事实

**不先理解这三条，写出来的代码一定会在多人并发时出问题。**

### 事实 1：每条消息 = 一个新线程 + 一个全新事件循环

```python
# Hyper/Adapters/OneBot.py
:193   asyncio.run(handler(...))              # 每条消息一个新事件循环
:265   threading.Thread(target=lambda: __handler(data, actions)).start()   # 每线程一条消息
```

**推论（都是硬约束）**：

| 结论 | 说明 |
|---|---|
| **`asyncio.Semaphore/Lock/Event` 不能跨消息复用** | 在循环 A 创建、拿到循环 B 用 → `attached to a different loop` 直接报错。要全局限流必须用 `threading` 原语 → 统一走 [Tools/concurrency.py](Jianer_Next_QQ_Bot/Tools/concurrency.py) |
| **模块级字典是裸的** | `user_lists`、`_voice_on` 这类全局字典被 100 条线程同时读写，无锁。计数/偏好这类状态一律进 SQLite 或加锁 |
| **CPU 密集活儿必须进受限线程池** | 否则 100 人同时发语音会各自开线程抢 GIL。用 `concurrency.run_cpu()` |
| **`asyncio.run` 返回时自动取消残留任务** | `presence.py` / `bubble.py` 的后台协程就靠这个收尾，**不需要手工回收** |

### 事实 2：`actions.custom.*` 是「发完就返回」，不等响应

```python
# Hyper/Adapters/OneBot.py:26-35
def __getattr__(self, item):
    async def wrapper(**kwargs):
        packet = Manager.Packet(str(item), **kwargs)
        packet.send_to(self.connection)
        return packet.echo          # ← 只是 echo 字符串，不是 API 返回值！
    return wrapper
```

**后果**：`try/except` 捕获不到 NapCat 的拒绝。所以
- 不要靠"没报错"判断调用成功 —— 要验证就真连一次 WS 发同样的包看 `retcode`；
- 但你的调用**绝不能**因为远端出错就崩：一律 `try/except` 静默降级。

### 事实 3：真正的瓶颈是给 QQ 发消息，不是 AI

流式回复会把一段话拆成多条发送（`AIKernal.MAX_MESSAGE_LENGTH`）。多人并发时发送速率会触发 QQ 洪水控制。
`concurrency.SEND_BUCKET` 是为此准备的全局令牌桶。

## 四、数据存储：`data/fox.db`（SQLite + WAL）

**为什么不用 JSON**：原 `voice_prefs.json` / `consent_asked.json` 是"整文件读-改-写"且无锁。
每条消息一个线程，多人并发必然丢更新，甚至写出截断 JSON（读的时候 `except` 静默返回 `{}`，
用户表现为"设置自己变回默认"）。这是真实存在过的数据损坏。

```sql
users(qq PK, nickname, card, gender, age, level, first_seen, last_seen,
      msg_count, voice_count, ai_count, char_count, active_days, streak_days,
      last_active_day, today_count, affinity, affinity_today, affinity_date,
      relation, nickname_pref, tags, note, revoked)
prefs(qq PK, voice, model, preset, extra)
group_prefs(group_id PK, voice, model, extra)
interactions(id, qq, ts, kind, group_id, summary)   -- 流水，90 天可裁剪
kv(scope, key, value)                                -- 承接 voice_prefs / consent
```

**关键实现约定**（改这个模块时必须遵守）：

1. **连接按线程持有**（`threading.local`）—— sqlite3 连接不可跨线程复用。
2. **计数用原子 SQL**：`SET x = x + 1`，不要"读出来加一再写回"。
3. **多语句用显式事务**：`BEGIN IMMEDIATE` … `COMMIT` / `ROLLBACK`。
4. **所有异常都吞掉并打印** —— 档案库故障绝不能拖垮聊天。
5. 首次运行自动迁移历史 JSON（`_migrate_json`，只在 kv 表为空时执行）。

**已验证**：50 线程并发写同一用户，`msg_count` 精确等于 51（零丢更新）。

## 五、并发准则（写任何新代码前过一遍）

| 场景 | 正确做法 |
|---|---|
| 全局限流（ASR/TTS/LLM 并发） | `concurrency.Gate` + `async with aslot(gate, timeout)` |
| 发消息速率 | `concurrency.SEND_BUCKET` 令牌桶 |
| 调用外部服务 | `CircuitBreaker` 熔断 + 指数退避重试 |
| 重复计算（同一段语音被转发） | `LRUCache` + `single_flight()` |
| CPU 密集（ffmpeg、whisper） | `await concurrency.run_cpu(fn, ...)` |
| 共享状态 | 进 SQLite，或 `threading.Lock` |
| 临时文件命名 | **必须用 `uuid4()`**（曾用"检查存在→递增"，并发下互相覆盖导致 A 听到 B 的语音） |
| 配置类 JSON 写盘 | 先写 `.tmp` 再 `os.replace`（原子），并加锁 |

## 六、如何扩展

### 加一个音色
编辑 [Tools/tts_voices.py](Jianer_Next_QQ_Bot/Tools/tts_voices.py) 的 `_V` 列表，加一行
`("友好名", "zh-CN-XxxNeural", "分类", "性别", ["标签"])`。
**不用管它能不能出声** —— 启动时的探活会自动判定，不能出声的不会展示给用户。
若音色是新语种，同时在 `_PROBE_TEXT_BY_PREFIX` 加对应探活文案（否则会被误判为不可用）。

### 加一个音效
在 `tts_voices.FX_PRESETS` 加 `"名字": "ffmpeg滤镜链"`。可用滤镜：`asetrate`/`atempo`/`aecho`/`aphaser`/`acrusher`/`vibrato`/`highpass`/`lowpass`。
注意：滤镜链**先 `aresample=24000` 归一化采样率**，否则 `asetrate` 的结果依赖输入采样率。

### 加一个模型
在 `config.json` 的 `Others.models.registry` 加一条：
```jsonc
{ "id": "sf-qwen", "provider": "silicon", "model": "Qwen/Qwen2.5-72B-Instruct",
  "label": "通义千问 72B", "tags": ["通用"], "aliases": ["千问"], "reasoning": false }
```
同时在 `providers` 里定义供应商（`type` 为 `openai` 或 `gemini`，`key_env` 指向环境变量）。
**不用改任何代码** —— `AIKernal` 按 `provider.type` 分派。
`tags` 参与 `~模型 自动` 的智能路由（`快` / `推理` / `多模态` / `离线`）。

### 加一个 ASR 后端
`Tools/asr.py` 目前只有 `_transcribe_local`（faster-whisper）。云端后端应遵循
**OpenAI 兼容的 `/v1/audio/transcriptions`**（硅基流动 / Groq / 阿里云 / 自建都通用）：
```python
client.audio.transcriptions.create(model=..., file=...)   # openai SDK 已装，零新依赖
```
注意：**云端省不掉 silk 解码** —— QQ 语音是 silk v3，必须先经 `_decode_silk_to_wav()`。

### 写一个插件
在 `plugins/` 放 `xxx.py`（文件名**不以 `d_` 开头**）：
```python
from Hyper import Configurator
Configurator.cm = Configurator.ConfigManager(Configurator.Config(file="config.json").load_from_file())
reminder = Configurator.cm.get_cfg().others["reminder"]

TRIGGHT_KEYWORD = "我的命令"        # 注意官方拼写就是 TRIGGHT
HELP_MESSAGE = f"{reminder}我的命令 —> 说明文字"

async def on_message(event, actions, Manager, Segments, order, ...):
    if "我的命令" not in order:
        return False                # False = 放行，交给后面的处理
    await actions.send(group_id=event.group_id,
                       message=Manager.Message(Segments.Text("hello")))
    return True                     # True = 拦截，不再走 AI
```
- 匹配是 **NFKC 归一化后的子串匹配**，关键词越短越容易误伤（历史上 `开` 曾遮蔽 `开群`）
- 参数按**名字**注入（`inspect.signature`），声明了但上下文没有、又没默认值 → 报错
- 关键词写 `"Any"` 的插件对**每条消息**都执行，不匹配时记得 `return False`
- 发图用 `Tools/img_send.py`，发语音用 `Tools/tts_local.py` 的 `speak_and_send`

## 八、已知问题与注意事项

1. **⚠️ 有另一个会话在同时编辑本目录源码**（`fox-console/` 那个项目会改 `config.json`，也有 agent 改过 `Tools/ai_backend.py`）。
   同时编辑同一文件会互相覆盖。改动前**先重读文件**，改完跑一遍语法检查。

2. **`fox-console/`** 是独立的图形化配置台（`127.0.0.1:5010`），**只读写配置类文件**，不碰机器人代码。
   它的规整函数明确保留未识别的键，所以新增配置项不会被它抹掉，但**暂时无法在它的界面里编辑**。

3. **AI 上下文**：`ContextManager` 的 Gemini `Context` 在创建时固化模型名，切模型必须重建（`~模型` 已经这么做了）。
   `user_lists` 的历史裁剪目前是 DeepSeek 链路里的 `history_limit=6`。

4. **Gemini 模型名**：`config.json` 的 `gemini_model` 与注册表里的 `gemini-flash` 是两处，改的时候别漏。

5. **ASR 并发上限**：本地 whisper 有串行锁（`_RUN_LOCK`）。单人用没问题，多人同时发语音会排队；
   要上量得接云端 ASR。

6. **`requirements.txt`** 里已补 `faster-whisper`/`pysilk`/`imageio-ffmpeg`/`pyttsx3`/`pywin32`/`nvidia-ml-py`。
   `models/` 里的 `faster-whisper-base` 必须包含 **`vocabulary.txt`**，缺了会报
   `Cannot load the vocabulary from the model directory`。

7. **PyAV 版本**：faster-whisper 1.2.1 调 `av.open(..., metadata_errors=...)`，而 PyAV 19 已移除该参数。
   `asr.py` 已改为**传 numpy 数组绕开 PyAV 解码**，不要再"顺手升级/降级 av"。

8. **判断音频格式要看文件头，不能看扩展名** —— edge-tts 保存出来的 `.wav` 内容其实是 MP3。
